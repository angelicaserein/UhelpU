# 录制系统功能说明（能做什么）

这份文档用大白话说清楚：录制系统**能做什么**、玩家看到的是什么、录进去的是什么、回放出来的是什么。

相关代码在：`js/record-system/`，Demo2 关卡文件在：`js/level-design/demo2/`。

---

## 1. 核心玩法概念

录制系统实现的核心机制叫"**与过去的自己合作**"。

操作流程：

1. 玩家**按下录制键**，开始录制自己的移动操作
2. 操作一段时间后**再次按下录制键**（或等到上限自动停止）
3. 游戏在玩家**录制起点位置**生成一个**分身**（Ghost/Replayer）
4. 玩家**按下回放键**，分身开始照着录制的操作重新走一遍
5. 玩家和分身可以**同时在场**，踩按钮、触发机关、过关

---

## 2. 录制的内容是什么

录制期间，系统只记录**玩家的按键操作**，不录制位置、速度等物理状态。

具体记录三类动作：

| 动作     | 触发键                   | 时间轴图标 |
| -------- | ------------------------ | ---------- |
| 向左移动 | 左方向键 / 绑定键        | ←          |
| 向右移动 | 右方向键 / 绑定键        | →          |
| 跳跃     | 空格 / 上方向键 / 绑定键 | ↑          |

每条记录的格式是：

- 是**按下**还是**松开**（keydown / keyup）
- 按的是哪个键
- 在录制开始后的**第几毫秒**发生

举例：录制一次"向右走两步再跳一下"，会记录：

```
t=0ms    keydown  ArrowRight
t=800ms  keydown  Space
t=900ms  keyup    Space
t=1200ms keyup    ArrowRight
```

---

## 3. 回放的内容是什么

回放时，系统把这些按键事件**按原始时序重新派发**一遍。

分身收到这些事件，就像玩家本人在按键一样，走出和录制时完全一致的路线和时机。

结果：

- 分身**能走路、能跳跃**
- 分身**能踩按钮**（触发关卡机关）
- 分身**能与场景碰撞**（有正常物理）
- 分身不会和玩家互相干扰（通常）

---

## 4. 录制时长限制

默认最长录制时间：**5 秒（5000ms）**

超过 5 秒会自动停止录制，进入准备回放状态。

可以在关卡初始化时修改：

```js
this.initSystems(this._player, 8000, { uiClass: Demo2RecordUI }); // 改成 8 秒
```

---

## 5. 分身在哪出现

分身出现在**玩家按下录制键时所站的位置**，不管玩家之后走到哪。

回放开始后，分身从那个起点出发，走录制时的路线。

---

## 6. 所有可用操作

| 玩家可做的事     | 状态                 | 触发方式                    |
| ---------------- | -------------------- | --------------------------- |
| 开始录制         | 准备录制中           | 按录制键（需在地面上）      |
| 停止录制         | 录制中               | 再次按录制键 / 超时自动停止 |
| 开始回放         | 录制结束/准备回放    | 按回放键                    |
| 提前结束回放     | 回放中               | 再次按回放键                |
| 重新录制（覆盖） | 准备回放（分身存在） | 按录制键覆盖，分身重置      |

---

## 7. 不能做的事（限制）

- **不能在空中开始录制**：起跳后不能按录制键，落地才能触发（防止起步状态不一致）
- **录制只认移动和跳跃**：其他按键（如交互键、暂停）不会被录下来
- **分身不会主动攻击/对话**：分身只复现移动操作
- **录制不保存**：关卡切换、玩家死亡后录制会被清空，需要重新录

---

## 8. 游戏暂停时的行为

游戏暂停后录制系统会"冻住"：

- 录制中暂停：计时停止，恢复后继续录，时间不丢失
- 回放中暂停：分身停止，恢复后继续从暂停时刻播放

暂停不会导致录制/回放时间短了或长了。

---

## 9. HUD 界面显示的内容

屏幕顶部常驻一个 HUD 面板（Demo2 风格：紫色系）：

| 区域   | 显示内容                                 |
| ------ | ---------------------------------------- |
| 左侧   | 当前状态标题（如"录制中"、"可以回放"）   |
| 右侧   | 当前可按的键和说明                       |
| 进度条 | 录制或回放的时间进度（已录 / 最长时限）  |
| 时间轴 | 每次操作（左/右/跳）的时间点用小图标标出 |
| 警告   | 在空中按录制键时显示"需要落地才能录制"   |

### HUD 四种状态对应内容

**准备录制**：提示按录制键开始，进度条为空

**录制中**：标题变成"录制中"，进度条增长，时间轴实时显示刚才的操作节点，计时 `已录X.Xs / 最长5.0s`

**准备回放**：进度条停在录制结束位置，显示"按回放键播放，按录制键重录"

**回放中**：分身开始移动，进度条从头跑到录制时长结束，计时 `已播X.Xs / 总时长X.Xs`

---

## 10. 操作时间轴（时间轴区域说明）

时间轴显示在 HUD 下半部分，是一条横向轴线，代表 0→录制时长。

每次按下左、右、跳时，在对应时间位置上插入一个小方块图标：

- `←` 蓝色 — 向左
- `→` 棕色 — 向右
- `↑` 橙色 — 跳跃

作用：帮助玩家快速了解自己录了什么，避免录错时间回放出错的情况。

---

## 11. 典型关卡使用场景

**场景一：双按钮同时踩**

- 关卡里有两个按钮，必须同时踩才能开门
- 玩家录制：走到按钮 A 踩住 → 停止录制
- 玩家回放：分身走到按钮 A → 玩家自己去踩按钮 B → 两个按钮同时被踩 → 开门

**场景二：踩弹跳平台**

- 玩家录制一段在弹跳平台上来回运动
- 回放后分身复现运动，触发机关开启通路

**场景三：时间差谜题**

- 某个机关在触发后 3 秒后关闭
- 玩家录制：跑到触发点 → 停止
- 玩家回放：分身去触发 → 玩家抓住开启的 3 秒窗口通过

---

## 12. 总结

录制系统本质上是一个"时间延迟复制器"：

- 录下的是**操作序列**（不是位置轨迹）
- 回放的是**完整重演**（用相同输入驱动分身物理）
- 核心体验是**与自己合作解谜**
